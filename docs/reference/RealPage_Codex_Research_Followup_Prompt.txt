2. PRIORITY ONE: ACTIONABLE MISSING-FACT NAVIGATOR

Build this over the existing evaluator. A generic list of all absent property fields is insufficient.

Preserve stable predicate IDs, field references, source references, AND/OR/NOT structure, and true/false/unknown results in the evaluation trace. Preserve enough of the residual expression to determine which unknown facts can still affect an outcome. If these already exist, consume them rather than adding a second representation.

Generate a bounded QuestionPlan for a lookup:
- Which property fact is needed, its precise meaning, data type/unit, and acceptable answer form.
- Why it matters, referencing the affected rules, predicate IDs, and evidence.
- Relevant alternative values or intervals.
- The evaluation resulting from each alternative, including all remaining uncertainty.
- A reproducible ranking rationale.
- Limits on the analysis, such as incomplete enumeration or an unsupported expression.
Use existing naming conventions and schemas; this is a conceptual contract, not a demand to invent another incompatible model.

Use partial evaluation and short-circuit semantics first. For supported Boolean or small enumerated domains, enumerate feasible alternatives. For numeric/date comparisons, partition the valid domain at the actual predicate thresholds and preserve inclusive/exclusive boundaries and date precision. Representatives are internal probes, never invented property facts.

Treat repeated uses of the same property field as one variable. Do not independently assign truth values to predicates that depend on the same fact and thereby create impossible branches. Respect known bounds and supplied relationships between facts.

A question can be useful even if answering it alone leaves the full rule unknown. Where bounded joint exploration is supported, establish materiality by finding feasible completions differing in that fact that change the outcome. Do not discard every question merely because another unresolved exemption remains. Conversely, do not ask about fields in branches already ruled out.

Use explicit exploration limits and deterministic ordering. Report a partial analysis when those limits are reached; do not turn an unexamined branch into certainty or claim an exhaustive/minimal question set. Do not add a general theorem prover for this MVP.

Rank questions using an explainable heuristic such as affected unresolved predicates or distinguishable outcomes divided by a small, documented answer-effort weight. These weights are heuristics, not probabilities. Tie-break deterministically. A simple well-tested ranking is preferable to a sophisticated but unverifiable planner.

Separate uncertainty remedies:
- Missing property fact: ask a factual question.
- Ambiguous jurisdiction/address: request the appropriate location clarification or evidence.
- Missing source or unresolved cross-reference: identify the source-retrieval/extraction gap.
- Unsupported legal condition or unresolved conflicting authority: identify the interpretation/review gap.
Do not ask a renter to supply a legal conclusion or resolve a source conflict.

Construction year does not automatically establish first-occupancy date, certificate date, or another distinct legal trigger. Ask for the actual fact required by the rule.

Accept supplemental answers through the existing request mechanism or a compatible extension. Validate them, record provenance as user-provided/verified/demo, scope them to the request or explicit scenario, and preserve the original benchmark data. Re-evaluate using the same evaluator. Both displayed alternatives and the result after a real answer must be reproducible through that evaluator.

Core and Platform must provide frontend-ready fixtures for: one decisive question; an irrelevant missing fact; two unresolved exemptions; unresolved source coverage; and a bounded/partial question analysis. The Frontend lane implements the interaction using these contracts; backend sessions leave frontend files to that lane.

3. PRIORITY TWO: SEPARATE EVIDENCE CHECKS AND EXPOSE WHAT THE RULE ENCODING SAYS

Reuse or strengthen the existing evidence pipeline.

Maintain distinct checks for:
- Source availability and identity/version.
- Citation or section anchor validity.
- Quoted-span presence in the source snapshot.
- Whether the cited context supports the extracted condition, threshold, exception, date, and interaction.
- Unsupported or unresolved dependencies.

A literal quote match proves the text occurs, not that it supports the interpretation. Lexical similarity is retrieval evidence, not semantic verification. An absent document in the supplied corpus is a coverage gap, not proof the law or authority does not exist. Keep these distinctions in machine-readable statuses and the handoff.

Use exact span references where possible. If normalizing whitespace/OCR for quote matching, record the transformation and retain a defensible mapping to the original source. Do not silently convert a fuzzy match into an exact quote.

Retrieve surrounding section context and explicit definitions, exception sections, and cross-references needed by a rule. Use the current source loader and a small in-process lexical index if necessary. Preserve section/source/span identity throughout retrieval. Never keep only the beginning of each chunk if that discards potentially decisive text. Mark missing references and cycles explicitly. Do not build an open-ended research agent.

Use a bounded semantic verification pass only where useful, comparing the proposed structured rule against supplied source passages and relevant dependencies. It may report supported, contradicted, or insufficient evidence, with supporting spans and specific discrepancies. The verifier must not substitute model memory for an absent source. Record live, fixture, and replay modes honestly. A model's self-rated confidence is not an accuracy measurement.

Add a deterministic AST-to-English renderer, or extend the existing explanation renderer, so a reviewer can see “what the encoded rule says” next to its source. It should preserve operators, grouping, dates, units, thresholds, exemptions, and unresolved/unsupported nodes. It must not use another LLM to invent a paraphrase of the law.

Keep this rule-level rendering distinct from a property-specific evaluation explanation. Both should derive from the same encoded rule. Stable output is useful for review and semantic diffs, but does not prove the legal interpretation is correct.

Where extraction omissions are a real gap, add a small source-unit inventory: provision/definition/exception/date -> source span -> mapped rule/predicate IDs, explicitly out of scope, or unresolved with a reason. If using a two-pass extraction approach, ground both passes in the original text; the first model's notes are not ground truth. Apply it selectively to consequential/risky documents and cache by source version and extractor version. Avoid needlessly reprocessing the full corpus.

Do not label model-detected inventory coverage as complete coverage of the law or as human-reviewed coverage.

4. REQUIRED VERIFICATION WITHIN EACH IMPLEMENTATION TASK

Extend the existing tests where these cases are missing. Prefer meaningful behavioral checks over tests that merely repeat the implementation.

Navigator:
- false AND unknown remains false; true OR unknown remains true.
- An irrelevant missing fact generates no question.
- With a synthetic rule “units >= 4 AND occupancy <= cutoff AND NOT exempt,” answering occupancy while exemption remains unknown does not create certainty.
- Correlated predicates on the same fact cannot produce impossible branches.
- Both hypothetical outcomes reproduce through the production evaluator.
- Question ranking is reproducible, and hitting the exploration budget is visible.

Evidence:
- A real quote used to support the opposite meaning does not pass merely because words overlap.
- A missing cross-referenced exception remains a visible gap.
- Missing source text does not become “no law,” “fabricated,” or verified inapplicability.
- Removing the only supporting evidence surfaces an evidence failure rather than leaving an unchanged verified result.
- The rule renderer preserves a changed comparison operator, exception, and effective-date boundary.

System:
- Removing a decisive fact creates the expected uncertainty; removing an irrelevant fact preserves the result.
- Crossing an effective date changes only the justified outcomes.
- Changing jurisdiction changes relevant local candidates while preserving unrelated property facts.
- Duplicate source ingestion does not duplicate rules.
- A whitespace-only source revision does not create a substantive legal change, while a threshold/exception/date change is detectable.

Use original synthetic fixtures for algorithmic traps and clearly label them. For actual legal correctness, add a small benchmark spanning the required categories, ordinary cases, and boundaries. Keep some examples out of active prompt tuning. Record who reviewed expectations; do not claim human review if none occurred. A model-generated expected answer checked by the same model is not an independent benchmark.

Report question counts, unnecessary questions, incorrect certainty, source-support failures, and exact cases tested where feasible. Compare the navigator to “ask every missing field” and “return generic unknown” on a small fixed set. Report denominators and limitations, not invented accuracy or official competition scores.
